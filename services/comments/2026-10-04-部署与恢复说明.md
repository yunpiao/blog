## 构建与部署

使用当前 Node.js LTS 或更新版本；所有命令在 `services/comments/` 内执行。

```sh
make help
make install
make upstream
make test
make test-upstream
make build
make deploy
```

`make upstream` 检出固定 Twikoo tag 并校验 commit，设置官方发布版本，应用可重复执行的小补丁，再构建官方 Cloudflare 入口。上游源码或补丁不匹配会停止，不应绕过检查。

本机 Cloudflare 登录权限若不足，可使用已登录的 `100.64.0.44`。本次 Tailscale CLI 使用显式 socket：

```sh
ssh -o BatchMode=yes -o ConnectTimeout=15 \
  -o 'ProxyCommand=/opt/homebrew/bin/tailscale --socket=/var/run/tailscaled.socket nc %h %p' \
  dongyunfei@100.64.0.44
```

把本机 `services/comments/.cloudflare/output/v0/` 的构建结果同步到远端工作目录的同名路径，再在远端部署：

```sh
cd ~/code/blog-comments-service-20261004
cf deploy --prebuilt
```

远端目录只需要构建产物；不要复制整个工作目录或本机口令文件。`cloudflare.config.ts` 是域名、D1 与邮件绑定、可观测性配置的事实源。

博客前端由 Hugo 构建。修改 `hugo.toml` 和主题后，验证 `hugo --minify`，再通过原 Git 发布流程更新网站。Worker 部署和博客静态发布是两个独立步骤。

本次前端提交 `070b166` 推送 `main` 后，EdgeOne 原有 Git 集成自动完成发布；正式页面于 2026-10-04 01:23（UTC+8）验证为新版本。发布有数分钟延迟，不应把推送成功等同于部署完成。GitHub 中另一个旧 Cloudflare Pages 检查失败不代表 EdgeOne 生产发布失败。

## 数据迁移与恢复

恢复应导入一个新的空数据库，先验证，随后修改 Worker 绑定；不要直接向当前数据库重放初始化与 INSERT。转换器在重复 ID、孤立回复、跨页面回复、循环关系和不支持的状态出现时停止。

```sh
node scripts/prepare-migration.mjs \
  /private/backup/waline-full-export.json \
  /private/backup/public-comments-flat.json \
  /private/new-migration-output
```

输出目录必须受限且为空。脚本以独占创建方式写入新管理口令、参数化 SQL 批次和迁移统计。使用 `cf d1 query DATABASE_ID --batch @/private/batch.json` 执行批次；schema 应先初始化。不要打印 `config` 表或导入批次。

### 配置恢复

本次仅修改上述七个字段，使用参数化 `json_set`，并核对目标字段旧值，避免覆盖其他配置。更新后重新读取验证：配置恰好一行、JSON 根为对象、七项均为预期字符串。

恢复资料在本机备份目录的 `mail-config/`：`before.json` 记录七项旧值，`restore.json` 是带并发校验的单条查询。目录权限 `700`，文件权限 `600`；不包含完整配置或 SMTP 凭据。执行恢复时将该对象放入单元素数组后使用 `cf d1 query DATABASE_ID --batch @批次文件`，批次文件同样使用 `600` 权限。预期只更新一行；零行表示目标配置已变化，应停止并检查，不能覆盖整行 `value`。

恢复七项后即可停止当前邮件通道；Worker、D1 和评论数据继续保留。邮件补丁的升级、收件限制及实现约束见 ADR。

## 回滚

Worker 保留版本历史，D1 与旧 Waline 导出独立保存。前端若需回滚，恢复本次迁移前的评论模板及配置并重新发布 Hugo；不要删除 D1 或旧服务。回滚后新写入 Twikoo 的评论不会自动出现在 Waline，必须先另行导出保存，避免丢失切换后的留言。
